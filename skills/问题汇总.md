# 问题汇总（skill-replace-search 使用 / 迭代记录）

> **用途**：记录使用本 skill（search / replace / defs / 配合 editor）时遇到的困难与问题，供后续迭代改进。
> **约定（必读）**：使用本 skill 遇到任何困难/坑/异常，**都要在本文件追加一条**，写清「日期 / 场景 / 现象 / 原因 / 处理（规避或已修复）」。这样每次迭代都有据可查，越用越稳。

## 如何记录（模板）

```
- 日期：YYYY-MM-DD
- 场景：在做什么 / 用了哪个命令
- 现象：发生了什么（报错、定位错、内容被破坏…）
- 原因：根因是什么
- 处理：怎么规避，或已修复（哪个改动）
```

## 已记录问题

### 1. findstr / Select-String 首个匹配常是「调用点」而非「定义」
- 日期：2026-08-12
- 场景：用 Select-String 定位 `StartMonitoring` 的定义行。
- 现象：被定位到 `Form.cs:164`（调用点），实际定义在 `Form.Monitoring.cs:17`。
- 原因：两个命令都返回**第一个出现位置**，方法名常先出现在调用处/事件连线/字段，而非定义。
- 处理：**已修复**——`replace_or_search.ps1` 新增 `-Action defs`，按签名特征（访问修饰符/返回类型 + `方法名(`）只找定义行，跳过调用点/事件连线/注释。以后定位定义一律用 `defs`；拿不准时用 `search` 列出全部出现、人工挑定义行。

### 2. read_files 会把单反斜杠显示成 `\\`
- 日期：2026-08-12
- 场景：回读规则 16，核对其中的反斜杠。
- 现象：显示 `scripts\\publish`，误以为文件里是双反斜杠。
- 原因：read_files 输出在显示/编码层把 `\` 转义成 `\\`。
- 处理：核对文件里反斜杠**数量别信显示**，用 `[char]92` 构造子串做 `Contains`，或字符计数校验（实测文件是单反斜杠）。

### 3. run_commands 的 JSON 边界会「剥反斜杠、把 \n 变真换行」
- 日期：2026-08-12
- 场景：用 PowerShell here-string 写更新日志（含 Windows 路径）。
- 现象：`scripts\publish` 写成 `scriptspublish`、`MCP\vm-script-compiler` 丢反斜杠；`\n` 变成真换行。
- 原因：`run_commands` 以 JSON 字符串传命令，`\` 是 JSON 转义符。
- 处理：写/改**含反斜杠或换行**的文本一律用 `editor`（字面量）；必须走 shell 时路径反斜杠双写 `\\`、换行用反引号 `` `r`n ``、写完回读。已固化为工作区「规则 16」。

### 4. editor 的 old_text 匹配常因引号/CRLF/中文失败
- 日期：2026-08-12
- 场景：替换 README 里 `"关键词"` 那一行。
- 现象：old_text 写成 `\"关键词\"` 匹配失败（text not found）。
- 原因：read 输出把 `"` 显示成 `\"`，照抄进 old_text 就匹配不到真实内容；CRLF 与 LF 也有差异。
- 处理：先 `read_files` 确认原文再精确复制；读输出里的 `\"` 在文件里是普通 `"`。小段用 old_text，大段整文件重写。已固化于规则 6。

### 5. editor 的 insert_line 传「多行 + 含反斜杠」内容偶发失败
- 日期：2026-08-12
- 场景：给 `replace_or_search.ps1` 插入 defs 分支。
- 现象：`insert_line` 报 `Invalid input`，改用 old_text 锚点替换成功。
- 原因：insert_line + 多行/含反斜杠内容在边界解析不稳。
- 处理：多行插入优先用 old_text 替换锚点行（把「目标行 + 插入内容」一起重写），而不是 insert_line。

### 6. Measure-Object -Line 统计行数不准
- 日期：2026-08-12
- 场景：算规则文件总行数以定插入位置。
- 现象：报 363 行，实际约 520 行，差点插错位置。
- 原因：`Measure-Object -Line` 与 `Select-String` 的 LineNumber 计数不一致（长行/空行处理差异）。
- 处理：确定行号一律以 `Select-String` 的 LineNumber 为准，别用 `Measure-Object -Line`。

### 7. CRLF vs LF 导致 `\n` 模式匹配失败
- 日期：2026-08-12
- 场景：用 `\n---\n` 定位规则文件页脚分隔线。
- 现象：匹配不到。
- 原因：文件是 CRLF（`\r\n`），不是 `\n`。
- 处理：用 `\r?\n` 兼容，或用 Select-String 定位，或先归一化行尾再处理。

### 8. Windows 长路径（node_modules）导致删除 / 发布失败
- 日期：2026-08-12
- 场景：发布脚本清理 `@mistralai` 与 node_modules 开发文件。
- 现象：长路径 `.d.ts`/`.ts` 报 `DirectoryNotFound`，在 `$ErrorActionPreference='Stop'` 下中断整个发布。
- 原因：Windows MAX_PATH 限制 + `Remove-Item` 对深层路径失败。
- 处理：发布脚本那两处 `Remove-Item` 改为 try/catch 非致命；删除深目录用 `robocopy <空目录> <目标> /MIR` 清空技巧。
