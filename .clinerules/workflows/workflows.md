
# 🚀 自动提交并推送代码工作流

本工作流旨在自动暂存所有更改、生成符合 Conventional Commits 规范的提交信息，并将代码推送到远程仓库。如果工作区无更改或推送过程出错，系统将给出明确的提示并自动终止流程。

---

## 📋 执行流程概览

 1. **检查工作区状态** - 判断是否有待提交的更改。
 2. **暂存所有更改** - 将新增、修改及删除的文件加入暂存区。
 3. **生成提交信息** - 分析差异并生成规范提交信息（含交互确认）。
 4. **提交更改** - 执行 `git commit`。
 5. **推送到远程** - 执行 `git push`。
 6. **报告结果** - 汇总提交详情。

---

## 🔍 步骤 1：检查工作区状态

首先检查当前工作区是否存在未提交的更改。

- **执行命令**：
  
    ```bash
    git status --porcelain
    ```

- **判断逻辑**：

  - **如果输出为空**（即没有任何更改）：
        1.  输出提示信息：
            > ✅ 工作区干净，没有需要提交的内容。工作流已终止。
        2.  **立即停止工作流**，不再执行后续步骤。
  - **如果有更改**：
        - 继续执行下一步。

---

## 📦 步骤 2：暂存所有更改

将当前目录下的所有变更（包括新增、修改、删除）添加到 Git 暂存区。

- **执行命令**：

    ```bash
    git add .
    ```

- **异常处理**：
  - 如果命令执行失败（例如权限不足）：
        1.  输出错误信息：
            > ❌ git add 失败，请检查文件权限。工作流终止。
        2.  **立即停止工作流**。

---

## ✍️ 步骤 3：分析变更并生成提交信息

分析暂存区的具体代码差异，智能生成符合规范的提交信息。

### 3.1 分析差异

- **执行命令**：

    ```bash
    git diff --cached
    ```

### 3.2 生成提交信息规范

根据差异内容，生成符合 **Conventional Commits** 规范的提交信息。
**标准格式**：

```markdown
<type>(<scope>): <subject>
<body>
```

**字段说明**：

| 字段 | 说明 | 可选值 |
| :--- | :--- | :--- |
| `type` | 变更类型 | `feat` (新功能), `fix` (修复), `docs` (文档), `style` (格式), `refactor` (重构), `perf` (性能), `test` (测试), `chore` (构建/工具) |
| `scope` | 影响范围 | 如 `api`, `ui`, `config` 等 |
| `subject` | 简短描述 | 不超过 50 个字符 |
| `body` | 详细描述 | 简要列出主要改动点（可选） |

### 3.3 交互确认

- **展示生成的信息**，并向用户询问：
    > 是否使用此提交信息？
- **用户响应处理**：
  - **输入 `n`**：
        1.  提示用户手动输入提交信息。
        2.  使用用户提供的信息作为最终提交内容。
    - **输入 `y` 或直接回车**：
      - 使用自动生成的信息作为最终提交内容。

---

## 📝 步骤 4：提交更改

使用最终确定的提交信息执行 Git 提交操作。

- **执行命令**：

    ```bash
    git commit -m "提交信息"
    ```

- **异常处理**：
  - 如果提交失败（例如空提交或存在合并冲突）：
        1.  输出错误信息：
            > ❌ 提交失败，请检查是否有冲突或未解决的文件。工作流终止。
        2.  **立即停止工作流**。
- **成功处理**：
  
  - 提交成功后，记录本次提交的哈希值（`commit hash`），用于最终报告。

---

## 📤 步骤 5：推送到远程仓库

将本地当前分支的提交推送到远程仓库（默认为 `origin` 的同名分支）。

- **执行命令**：

    ```bash
    git push
    ```

- **异常处理**：
  - 如果推送失败（例如网络异常或远程仓库有新提交）：
        1.  输出错误信息：
            > ❌ 推送失败，请检查网络或先执行 git pull。工作流终止。
        2.  **立即停止工作流**。
- **成功处理**：
  - 推送成功，继续执行下一步骤。

---

## 📊 步骤 6：报告结果

推送成功后，汇总并输出以下关键信息：
**所需数据获取**：

- 当前分支名：`git rev-parse --abbrev-ref HEAD`
- 远程仓库 URL：`git remote get-url origin`
**输出模板**：

> ✅ **代码已成功提交并推送！**
>
> - **提交信息**：`<提交信息>`
> - **提交哈希**：`<commit-hash>`
> - **分支**：`<当前分支名>`
> - **远程仓库**：`<远程仓库 URL>` ```
